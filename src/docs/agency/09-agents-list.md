## Data Model Reference

Each agent conforms to the `CatalogAgent` interface:

```typescript
interface CatalogAgent {
  id: string;           // Unique identifier (kebab-case)
  slug: string;         // URL slug (same as id)
  name: string;         // Display name
  emoji: string;        // Emoji avatar for UI
  role: string;         // One-line role description
  tagline: string;      // Marketing tagline
  icon: LucideIcon;     // Lucide icon component
  color: string;        // Hex color for division
  division: Division;   // One of 10 divisions
  description: string;  // Full description paragraph
  capabilities: string[];    // 5-6 specific capabilities
  mission: string[];         // 3 mission objectives
  rules: string[];           // 3 operating rules
  successMetrics: string[];  // 3 measurable KPIs
  industries: string[];      // Target industries
  goals: string[];           // Business goals this agent serves
  pairsWith: string[];       // Complementary agent names
  useCases: AgentUseCase[];  // Example input/output scenarios
  assignedTo: string[];      // Demo client assignments
  isCurated: boolean;        // true = shown in default catalog view
}
```

## How Agents Are Used

| Surface | Source | Count | Notes |
|---------|--------|-------|-------|
| Wizard Steps 3-5 | `agentData.ts` `matchAgents()` | 4-6 per client | Local deterministic matching by system + industry |
| Dashboard Agent Team Widget | `POST /agents/match` with fallback to `matchAgents()` | 4-6 per client | Shows fit scores, status, last run |
| CRM Deal Scoring | `dealScoring.ts` | 2 (Pipeline Analyst, Deal Strategist) | Deterministic scoring based on deal attributes |
| Agent Catalog pages | `ALL_CATALOG_AGENTS` | 116 | Browsable directory with division filters |
| Agent Detail page | `getAgentBySlug()` | 1 | Full profile with capabilities, metrics, use cases |
| Agent Runner | `agent-loader.tsx` `compilePrompt()` | 1 per run | Gemini-powered execution with 4-layer prompt |
